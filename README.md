# 教师关怀资源公平分配

教师服务中心用本服务在**最少披露个人情况**的前提下，完成关怀申请的资格核验、优先级调整、
资源占用与候补递补。心理咨询、临时减课、同伴支持名额均按结构化政策分配，
每一次分配选择都可由负责人独立复算，容量在并发下不可能被突破。

请使用 Node.js 20 或更高版本，零第三方依赖：

```bash
npm test    # 领域、加密、并发容量、最小披露、HTTP 与持久化恢复等性质测试
npm start   # 启动 HTTP 服务（需配置密钥环境变量）
```

## 设计如何对应诉求

| 诉求 | 实现 |
| --- | --- |
| 最少披露、敢于求助 | 排队库只保存教师身份的 **SHA-256 指纹**（不可逆、可识别重复申请）；敏感说明经 **AES-256-GCM** 加密后存放在**物理分离**的独立目录，排队事件中只有 `hasNote` 布尔位 |
| 可预期的处理进度 | 教师查询自己的阶段与等待解释：位置、前方各紧急度人数、资源占用/总量——只有聚合数字，绝无任何他人申请编号或身份 |
| “后来的紧急申请先获得”可解释 | 确定性排序：紧急度（immediate > priority > standard）→ 提交时间 → 申请编号；每次分配事件记录当时**完整候选排序与每人核验结果** |
| 容量不被并发突破 | 全部写操作经单写者串行事务；“检查容量→选队首→占用”是原子的；槽位 `alloc/release` 严格配对，双重占用在投影层直接抛错 |
| 资源释放后按当时有效优先级递补 | 完成/爽约/撤回均释放槽位并立即递补；递补前用**当前政策**重新排序、重新核验 |
| 证明过期不占名额 | 提交、续交、政策换版、**每次递补前**都复验；过期候补退回 `submitted` 并记录结构化原因，跳过但不阻断后续人 |
| 重复申请不双占 | 同一教师同一资源已有候补/占用申请即判重复；申诉未决同样阻断新申请 |
| 爽约与冷静期 | 爽约关闭并按资源进入冷静期（默认 30/14/14 天），期内新申请不合格 |
| 申诉不重复占名额 | 申诉成立只把申请**重新放回候补队列**；名额在爽约关闭时即已释放并已被递补，复职不持有任何槽位 |
| 规则版本只作用于未承诺申请 | 政策版本化、不可变；申请快照适用版本；`allocated/closed` 为“已承诺”，新版本只重验 `submitted/waiting`；缩容不收回承诺，扩容立即生效 |
| 经办角色边界 | 教师：提交/撤回/续证明/申诉/查自己；经办人：列表、升级（immediate 需理由代码）、登记结果、复核、读敏感说明（留 `NoteRead` 审计）；负责人：激活政策、资源总览、复算 |

## 数据与事件

- 排队事实来源：仅追加的 `events.jsonl`（提交、核验、升级、撤回、分配决策、释放、关闭、申诉、政策激活、审计）。
  内存读模型只是投影，可随时从日志完整重建（重启恢复即如此）。
- 敏感说明：`<sensitive-dir>/<APP_ID>.note.enc`，密文信封带版本号，AAD 绑定申请编号，换号或篡改均解密失败。
- 两者目录相同将拒绝启动。

## HTTP 接口（节选）

认证：`Authorization: Bearer <token>`，教师身份取自令牌声明，请求体不能自报身份。

- `POST /applications` 教师提交（不可自报 `immediate`，仅经办可升级）
- `GET  /applications/:id` 本人视图（阶段 + 聚合化等待解释）
- `POST /applications/:id/withdraw` · `/renew-proof` · `/appeals`
- `POST /applications/:id/escalate` · `/outcomes`（经办）
- `POST /applications/:id/review/start` · `/review/resolve`（经办）
- `GET  /applications/:id/note`（经办人，读取留审计）
- `GET  /worker/applications?resource=`（经办/负责人，无敏感明文、无真实身份）
- `POST /allocations/run?resource=`（经办/负责人，手动触发分配/递补）
- `GET  /director/resources` · `GET /director/recompute`（负责人）
- `POST /policies`（负责人，激活新版本政策）

复算从事件日志独立重放，校验：选中者是否确为当时合格队首、考虑顺序是否符合确定性排序、
分配前后占用是否与快照一致且不超容量、槽位是否双重占用；篡改任何分配决策都会被检出。

## 配置（受控环境注入）

- `CARE_DATA_DIR`：排队事件目录（默认 `./.data/queue`）
- `CARE_SENSITIVE_DIR`：密文目录（默认 `./.data/sensitive`，必须与上者分离）
- `CARE_VAULT_KEY`：base64 编码的 32 字节密钥；或 `CARE_VAULT_PASSPHRASE`（仅开发/测试）
- `CARE_PORT`：监听端口（默认 3000）

加密密钥、真实证明材料和个人身份数据必须留在受控环境中；演示令牌表见 `src/http.js`，
生产必须替换为受控令牌/身份提供方。

## 源码

- `src/domain.js`：资源、状态、紧急度、角色权限等公共词汇
- `src/policy.js`：结构化、版本化政策与校验
- `src/crypto.js`：AES-GCM 保管、教师指纹、敏感存储
- `src/store.js`：仅追加事件日志（文件版/内存版）
- `src/projector.js`：事件 → 读模型的确定性折叠
- `src/service.js`：串行事务、资格核验、排队、分配/递补、申诉、视图、复算
- `src/http.js` / `src/server.js`：HTTP 适配与启动装配
